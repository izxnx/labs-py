# Лабораторна робота № 3

**Тема:** прикладні бібліотеки Python для побудови вебзастосунків.  
**Варіант:** 8 — облік часу відновлення сервісів.

## Предметна область

Сервіс зберігає навчальні вимірювання тривалості відновлення трьох сервісів:
`database`, `web_service` та `file_storage`. Поле `value` містить невід'ємний
час у хвилинах; навчальний поріг — **60 хв**. Запис має код, назву, категорію,
час та стан опрацювання (`new`, `in_progress` або `done`). Початковий набір
містить три категорії та вісім вимірювань із методички.

## Встановлення та запуск

Команди виконуйте з кореня `cybersecurity-python-labs` у віртуальному
середовищі Python 3.10 або новішому:

```powershell
python -m pip install -r requirements.txt
python -m labs.lab03.seed
python -m uvicorn labs.lab03.main:app --reload --host 127.0.0.1 --port 8000
```

`seed` створює схему та додає категорії й записи однією транзакцією. Повторний
запуск не створює дублікатів. API під час запуску створює відсутні таблиці,
але не змінює початкові дані. Swagger UI доступний за адресою
<http://127.0.0.1:8000/docs>, OpenAPI — <http://127.0.0.1:8000/openapi.json>.

## Маршрути

| Метод і шлях | Призначення | Успішний код |
| --- | --- | --- |
| `GET /ping` | Перевірити доступність | 200 |
| `GET /student` | ПІБ, група та варіант із `shared/student.py` | 200 |
| `GET /categories` | Отримати категорії | 200 |
| `POST /categories` | Створити категорію | 201 |
| `DELETE /categories/{category_id}` | Видалити порожню категорію | 204 |
| `GET /records` | Список, фільтри та сторінки | 200 |
| `GET /records/{record_id}` | Отримати один запис | 200 |
| `POST /records` | Створити запис | 201 |
| `PUT /records/{record_id}` | Повністю замінити змінювані поля | 200 |
| `DELETE /records/{record_id}` | Видалити запис | 204 |
| `POST /records/bulk` | Атомарно створити 1–100 записів | 201 |

Помилка перевірки запиту повертає `422`; відсутній запис або категорія —
`404`; дублікат коду/назви або видалення непорожньої категорії — `409`.
Відповідь `204` не має тіла. Невідомі поля в тілі запиту заборонені.

## Фільтрація записів

`GET /records` приймає `category_id` (>0), `status`, `min_value` (хв), `q`
(буквальний регістрозалежний підрядок у назві, 1–120 символів), `limit`
(1–100, типово 20) та `offset` (типово 0). Кілька фільтрів поєднуються через
`AND`; результати завжди впорядковані за зростанням `id`. Наприклад:

```text
GET /records?category_id=1&status=new&min_value=60&limit=5&offset=0
GET /records?q=%27%20OR%201%3D1%20--
```

Для пошуку використовується `instr(title, ?)`, тому `%`, `_` і SQL-подібний
текст є звичайними даними. Усі значення SQL-запитів передаються параметрами.

## Приклади PowerShell

Створити вимірювання:

```powershell
$record = @{
    code = 'V08-DEMO'
    title = 'Перевірка відновлення API'
    category_id = 2
    value = 48.5
    status = 'new'
} | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8000/records' `
    -ContentType 'application/json' -Body $record
```

Додати пакет однією транзакцією:

```powershell
$batch = @(
    @{ code = 'V08-B01'; title = 'Пакетне вимірювання 01'; category_id = 1; value = 32.0; status = 'new' }
    @{ code = 'V08-B02'; title = 'Пакетне вимірювання 02'; category_id = 3; value = 52.0; status = 'in_progress' }
) | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8000/records/bulk' `
    -ContentType 'application/json' -Body $batch
```

Для повної заміни через `PUT` передайте всі п'ять змінюваних полів: `code`,
`title`, `category_id`, `value` та `status`. Ідентифікатор запису визначається
лише адресою маршруту.

`.gitignore` правила не дозволяють випадково включити базу або її journal/WAL
файли до Git. Усі дані навчальні.

Деталі реалізації, перевірки API, транзакції та висновки наведено у
[`REPORT.md`](REPORT.md).
